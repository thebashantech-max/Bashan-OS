# Bashan OS — Localization

13 shipped languages: English, Spanish, German, French, Portuguese,
Kurdish Kurmanji, Russian, Greek, Arabic, Hebrew, Syriac, Sorani, Persian.

All Bashan-specific strings (welcome app, installer additions, dock tooltips,
boot-song toggle) are translated into all 13.

## Known upstream gaps — re-verified against trixie, Stage 4

Checked by installation candidate inside the build container, not by name
lookup. Two Stage 1 assumptions turned out to be wrong and are corrected here.

| Language | LibreOffice UI | Spellcheck | Notes |
|---|---|---|---|
| English | yes | `hunspell-en-us` | |
| Spanish | `libreoffice-l10n-es` | `hunspell-es` | |
| German | `libreoffice-l10n-de` | `hunspell-de-de` | |
| French | `libreoffice-l10n-fr` | `hunspell-fr` | |
| Portuguese | `libreoffice-l10n-pt` | `hunspell-pt-pt`, `-pt-br` | |
| Russian | `libreoffice-l10n-ru` | `hunspell-ru` | |
| Greek | `libreoffice-l10n-el` | `hunspell-el` | |
| Arabic | `libreoffice-l10n-ar` | `hunspell-ar` | RTL |
| Hebrew | `libreoffice-l10n-he` | `hunspell-he` | RTL |
| **Persian** | `libreoffice-l10n-fa` | **`myspell-fa`** | RTL. **Correction:** Stage 1 recorded Persian as having no dictionary. It has one — as a myspell package, which LibreOffice reads via `dictionaries-common`. Persian gets both a translated UI and spellcheck. |
| **Kurmanji** | **none** | **none** | `libreoffice-l10n-ku` does not exist. **Correction:** `hunspell-ku` does not exist either — only `aspell-ku`, which LibreOffice does not use. So Kurmanji has no office spellcheck, not just no translated UI. Locale is `ku_TR` only. |
| **Sorani** | **none** | **none** | No UI translation, no dictionary of any kind. Weak upstream coverage overall. |
| **Syriac** | **none** | **none** | No UI translation, no dictionary of any kind. Weak upstream coverage overall. |

Kurmanji, Sorani and Syriac therefore get the **English** LibreOffice UI with
correct RTL handling and fonts, and the installer says so plainly.

Coverage of KDE and system strings beyond this table has **not** been verified
yet and must not be claimed. Stage 8 does the full pass.

## Installer language coverage — verified, Stage 7B

Two different things, often confused, so stated separately.

**1. The language the installer itself speaks.** This comes from Calamares'
own translations. The authoritative list for Calamares 3.3.14 has 81
languages in four completeness tiers, taken from upstream's `CMakeLists.txt`:

| Our language | Calamares code | Upstream tier |
|---|---|---|
| English | `en` | **complete** |
| German | `de` | **complete** |
| Spanish | `es` | good |
| French | `fr` | good |
| Hebrew | `he` | good |
| Portuguese | `pt_PT` | good |
| Russian | `ru` | good |
| Arabic | `ar` | ok (partial) |
| Greek | `el` | ok (partial) |
| Persian | `fa` | ok (partial) |
| **Kurmanji** | — | **no translation at all** |
| **Sorani** | — | **no translation at all** |
| **Syriac** | — | **no translation at all** |

So 10 of 13. Arabic, Greek and Persian sit in Calamares' "ok" tier, meaning
some strings fall back to English mid-screen. Kurmanji, Sorani and Syriac
do not appear in the installer's language list at all — they are not
languages Calamares has ever been translated into.

**2. The language the installed system speaks.** This is a separate choice
and is **not** limited the same way. Every one of the 13 exists in glibc and
is generated into the image:

| Language | Locale | Note |
|---|---|---|
| English | `en_US.UTF-8`, `en_GB.UTF-8` | |
| Spanish | `es_ES.UTF-8` | |
| German | `de_DE.UTF-8` | |
| French | `fr_FR.UTF-8` | |
| Portuguese | `pt_PT.UTF-8`, `pt_BR.UTF-8` | |
| Russian | `ru_RU.UTF-8` | |
| Greek | `el_GR.UTF-8` | |
| Arabic | `ar_SY.UTF-8`, `ar_EG.UTF-8` | RTL |
| Hebrew | `he_IL.UTF-8` | RTL |
| Persian | `fa_IR` | RTL. No `.UTF-8` suffix form exists |
| Kurmanji | `ku_TR.UTF-8` | Only `ku_TR`. No `ku_IQ`, no `ku_SY` |
| Sorani | `ckb_IQ` | Region suffix mandatory; plain `ckb` does not exist |
| Syriac | `syr` | RTL. No region suffix exists |

**What this means in practice.** A Kurmanji, Sorani or Syriac speaker runs
the installer in English (or Arabic), and still gets their own language as
the installed system language. They lose the installer's wording, not the
system. Worth saying plainly in any user-facing documentation.

Verified by checking each entry against glibc's `SUPPORTED` list inside the
build container, not from memory. All 16 locale entries are generated at
build time by `hooks/chroot/0300-locales.hook.chroot`.

## Bashan's own strings — Stage 8

20 user-facing strings that are ours rather than upstream's: the Bashan app
launcher, the Chrome placeholder and its installer dialogs, the installer
desktop icon, the four slideshow slides, and the language note. They live in
one catalogue, `i18n/strings.json`, and `scripts/40-i18n.py` turns that into
every form the system needs:

| Output | Used by |
|---|---|
| `Name[xx]=` / `Comment[xx]=` merged into the `.desktop` files | the dock and app menu |
| one POSIX shell catalogue per language | `/usr/bin/bashan-install-chrome` |
| a JavaScript map embedded in `show.qml` | the installer slideshow |
| `i18n/REVIEW.csv`, 240 rows | a native speaker |

### Translation confidence — read this before trusting any of it

**None of these has been checked by a native speaker.** The confidence
column is an honest self-assessment, not a quality guarantee:

| Language | Confidence | What that means |
|---|---|---|
| English | source | written, not translated |
| Spanish, German, French, Portuguese, Russian | high | expected to be correct and natural; still unreviewed |
| Greek, Arabic, Hebrew, Persian | good | expected to be correct; phrasing may read slightly stiff |
| **Kurmanji** | **LOW** | plausible but unverified; grammar and terminology likely need correction |
| **Sorani** | **LOW** | as above |
| **Syriac** | **VERY LOW** | a low-resource language. Treat this as a placeholder that proves the plumbing works, not as a translation |

Every build prints a warning naming the unreviewed languages. That warning
stays until someone sets `reviewed: true` in `i18n/strings.json`, which
should only happen after a native speaker has been through `REVIEW.csv`.

`i18n/REVIEW.csv` has one row per string per language, with the English
source, our attempt, an empty `CORRECTED_TRANSLATION` column and a notes
column. It opens in LibreOffice Calc.

The Syriac **font** choice needs a native eye too: `Estrangelo Edessa` is
set as the default because it is the most widely used digital Syriac face,
but whether Serto or East Syriac suits this audience better is not
something that can be decided from outside the language.

## Right-to-left handling — Stage 8

**Almost all of it is automatic.** Qt mirrors the entire interface when the
locale is RTL: the dock flips so the Bashan logo launcher sits at the right
edge, menus open the other way, Dolphin's panes swap, scrollbars move, text
aligns right. Nothing needs configuring and nothing is hand-built.

**One thing is not automatic.** Free-floating desktop widgets have absolute
coordinates, so the Trash icon stays wherever it was put. That is what
`/usr/libexec/bashan/bashan-desktop-locale` fixes:

| Corner | Languages |
|---|---|
| bottom **right** | English, Spanish, German, French, Portuguese, Kurmanji, Russian, Greek |
| bottom **left** | Arabic, Hebrew, Syriac, Sorani, Persian |

It runs at every login, compares the current locale against the last one it
acted on, and does nothing if they match — so a later language change is
picked up at the next login, and an unchanged login costs nothing.

It drives plasmashell's own scripting interface over D-Bus rather than
editing `plasma-org.kde.plasma.desktop-appletsrc`. The config format for
widget geometry is internal and changes between Plasma releases; the
scripting API is public and applies live. If anything is missing the script
exits quietly and the icon stays bottom-right, which is cosmetic.

Kurmanji is in the left-to-right group: it is written in Latin script.
Sorani is in the right-to-left group: it is written in Arabic script. Same
language family, opposite direction.

## Fonts per language — Stage 8

`/etc/fonts/conf.d/60-bashan-languages.conf`, 11 fontconfig rules. Chosen
over per-user settings because fontconfig is the one mechanism that applies
to Qt, GTK, the browser and LibreOffice at once, needs no login script, and
survives a language change.

| Language | Sans | Serif |
|---|---|---|
| Arabic | Noto Sans Arabic, Scheherazade | Amiri, Scheherazade |
| Persian | Noto Sans Arabic, Nazli | Nazli, Scheherazade |
| Sorani | Noto Sans Arabic, Lateef | Lateef, Scheherazade |
| Hebrew | Noto Sans Hebrew, Nachlieli CLM | Frank Ruehl CLM, David CLM |
| Syriac | Estrangelo Edessa, Serto Jerusalem | Estrangelo Edessa, East Syriac Adiabene |

Every family name was read out of the font packages with `fc-query`. Worth
noting: the SIL family in trixie is `Scheherazade`, **not** `Scheherazade
New` — the name most documentation gives. Guessing would have produced
rules that silently did nothing.

## RTL

RTL languages: Arabic, Hebrew, Syriac, Sorani, Persian. These mirror the dock
(logo launcher moves to the right) and place the desktop trash icon bottom-left.
